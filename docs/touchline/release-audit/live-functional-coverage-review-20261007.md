## Concrete harness sensitivity issue (medium coverage risk, high confidence)

`active.polls++` precedes the request branch. The check only requires a request attempt; it never asserts per-case `held` or `fulfilled`, nor waits for the success/error outcome before selection/screenshots. Consequently an image labelled error can merely show the preloaded stale fixture before the 503 is handled, and releasing a pending request establishes no recovery assertion. Add per-case response/body-settlement readiness and distinct recovery facts. Keep console classification restricted to exact synthetic 503 endpoint/case; no generic suppression. Do not increase broad timeouts to conceal this.
